Overview

Introduction

YOLOv3 is a widely used and effective object detection network with high accuracy and performance. YOLOv3 is the third version of the YOLO series. Compared with YOLOv2, YOLOv3 integrates some good solutions into YOLO to improve the prediction accuracy while maintaining the speed advantage. In particular, YOLOv3 enhances the capability of identifying small objects. YOLOv3 has the following improvements: the network structure is adjusted; multi-scale feature is used to detect objects; replaces the softmax with the logistic classifiers for object classification.

The YOLOv3 provided by Ascend is based on the third-party TensorFlow open-source code, uses DarkNet-53 as the backbone network, and supports both single-scale and multi-scale training.

Reference: Redmon, Joseph, and Ali Farhadi. YOLOv3: An Incremental Improvement.

Implementation: https://github.com/wizyoung/YOLOv3_TensorFlow

Default Configuration

  • Training dataset preprocessing (The COCO 2014 training set is used as an example.)

    Set the input image size to 416 x 416 for single-scale training.

    For multi-scale training, the value can be 320 x 320, 352 x 352, 384 x 384, 416 x 416, 448 x 448, 480 x 480, 512 x 512, 544 x 544, 576 x 576, or 608 x 608.

    Image input formats: JPEG

    Randomly dither color.

    Set the input image size to 416 x 416. (Resize the width of an image to 416, maintain the aspect ratio, and crop the image in the center.)

    Image input formats: JPEG

    Normalize the image to 0-1.

Supported Features

The following features are supported: distributed training, mixed precision, and data parallelism.

8-device training script, supporting parallel distributed training. By default, the mixed precision is enabled in the script. For details, see "Enabling Mixed Precision."

The 8-device training script supports distributed training of parallel data. YOLOv3 supports multi-scale training. During training, 10 images with different sizes are randomly input as the input of the model, which can improve the model accuracy to some extent. You can use the built-in multi-scale training script and parameter settings of the project for training. For details, see Quick Start.

Mixed Precision Training

Ascend 910 AI Processor provides the automatic mixed precision function. For operators of the FP32 data type on the entire network, some FP32 operators can be automatically converted to FP16 operators based on the built-in optimization policy. In this way, the system performance is improved and the memory usage is reduced with little accuracy loss.

Quick Start

  1. Click in the upper right corner and select a download method to download the source code package.
  2. Prepare datasets.

    1. Prepare a training dataset and a validation dataset. COCO 2014 and COCO 2017 are recommended. The default path for reading the dataset in the script is /opt/npu/dataset/coco. You can soft link the actual data to the default path to simplify operations.
    2. In the training script that is provided in this section, the COCO 2014 dataset is used as an example to describe how to preprocess data during training. To modify the dataset, modify the dataset loading and preprocessing methods in the training script before using the script.
    3. Use coco_trainval_anns.py and coco_minival_anns.py to generate the training and validation sample annotation files coco2014_trainval.txt and coco2014_minival.txt respectively based on the actual path of the COCO 2014 dataset, and save them to the data directory. In the code repository, the annotation has been generated in the data directory based on the default dataset location. If the actual dataset directory is the same as the default directory, skip this step.

  3. Prepare a pre-trained model. Loading the ImageNet pre-training parameters to the backbone of the detection model can effectively avoid model non-convergence and accelerate model convergence. Therefore, it is recommended that the ImageNet pre-training parameters are downloaded. Download the pre-trained model in the Darknet framework from https://pjreddie.com/media/files/darknet53.conv.74 and use the convert_weight.py script to convert the model to a checkpoint file in TensorFlow framework. By default, the Darknet pre-training weight is read from ./data/darknet_weights/. Set restore_path to the path of the converted checkpoint file in Step 4.
  4. Change related paths in the args_single.py (single-scale) or args_multi.py (multi-scale) configuration file to the actual paths. Table 1 describes the fields.

    Table 1 Configuration file description

    Field

    Description

    work_path

    Absolute path of the project (configured before training)

    train_file

    Path of a training sample annotation file

    val_file

    Path of a validation sample annotation file

    restore_path

    Path for storing a pre-trained model

    anchor_path

    Path for storing an anchor file

    class_name_path

    Path for storing a class name file

Script Options

In this project, the training parameters are configured by modifying the args_multi.py and args_single.py files. The configurable fields in the two files are the same. You do not need to transfer parameters by scripts. The args_multi.py is used as an example to describe the configurable parameters.

Obtaining Data

If you want to use your own dataset for training, perform the following steps to prepare data:

  1. Generate annotation files for the training dataset and validation dataset, for example, train.txt and val.txt. Each line indicates a sample. The format is as follows:

    image index | image path | box1_class box1_xmin box1_ymin box1_xmax box1_ymax | box2_class box2_xmin box2_ymin box2_xmax box2_ymax | ...

  2. Use the clustering algorithm to generate an anchor file required by the model based on the sample and save the anchor file as a .txt file.
  3. Generate a text file containing all class names based on the sample.

The training process script with the dataset is for reference only.
