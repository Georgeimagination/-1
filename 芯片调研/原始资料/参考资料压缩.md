# 参考资料压缩

这轮调研先把资料尽可能收全，再根据 36 个芯片 SKU 的实际信息需求筛选来源。初始资料池覆盖官方规格书、数据手册、架构白皮书、厂商论文、开发文档、产品页、发布说明、独立微基准和专业媒体。最终资料库只保留能够直接支撑资料卡内容、引用位置清楚、对象层级正确的来源。

压缩的对象是正式引用集合，原始资料没有删除。被排除的资料仍留在候选池中，后续遇到来源冲突或需要追溯时可以重新查阅。

## 从候选资料池到最小引用集合

[资料汇总统计](清单/汇总统计.json)记录了 111 份去重后的 PDF 和 893 个合并去重的在线 URL，共 1,004 个候选资料条目。PDF 与在线 URL 分别去重，两类之间可能存在交叉，因此 1,004 表示候选条目规模，不解释为跨介质完全无重合的唯一来源数。

截至 2026 年 8 月 25 日，活动资料目录实际保存了 121 份 PDF 和 52 份网页快照。经过逐款阅读和筛选，[36 张 SKU 资料卡](../../待调研芯片清单.md)共列出 233 条卡片级参考资料，合并相同链接或本地文件后对应 186 个来源目标。每张卡使用 2 至 10 条参考资料，平均约 6.5 条。

| 统计对象 | 数量 | 口径 |
|---|---:|---|
| 去重 PDF 清单 | 111 份 | 初始汇总阶段的唯一 PDF |
| 合并在线资料 | 893 个 URL | 两套在线来源清单合并后的唯一 URL |
| 当前本地资料 | 121 份 PDF、52 份网页快照 | 截至 2026-08-25 的活动资料目录实存文件 |
| 正式调研对象 | 36 个 SKU 或官方 per-chip 配置 | 覆盖 Google、NVIDIA、AWS、AMD、华为、Groq 和寒武纪 |
| 资料卡引用 | 233 条 | 同一来源被不同 SKU 复用时分别计入 |
| 最小来源目标 | 186 个 | 对资料卡中的链接和本地文件目标合并去重 |

以 1,004 个候选条目和 186 个最终来源目标作工作量口径，约 18.5% 的候选资料进入了本轮最小引用集合。其余候选条目没有进入最终资料卡，主要原因是信息重复、证据等级较低、无法定位原文、对象层级不符，或者没有为资料卡增加新的事实。

## 参考资料覆盖了哪些类型

资料池没有局限在官方数据手册。已归档的 111 份去重 PDF 中，包括 28 份厂商或芯片设计团队直接发表的架构论文、16 份官方白皮书与技术资料、53 份独立逆向分析与微基准论文，以及 14 份系统和性能补充资料。在线清单还登记了官方产品页、开发文档、发布说明、论文与会议入口、DOI、在线 PDF、专业媒体和第三方分析。在线记录合并相同 URL 后得到前述 893 个入口。

不同资料承担的证明任务不同。下面按实际用途列出本轮接触过的主要类型；是否进入最终资料卡，仍取决于它能否为某个字段提供独有、可定位的证据。

| 资料类型 | 典型内容 | 主要用途 | 使用边界 |
|---|---|---|---|
| 官方规格书、数据手册和 Product Brief | 峰值算力、精度、内存、接口、功耗、尺寸和工作条件 | 固定具体 SKU 的公开规格 | 营销标题不能替代规格表；卡、模组和系统参数不能直接写成芯片参数 |
| 官方架构白皮书和技术白皮书 | Core、die、chiplet、cache、NoC、内存系统、互联和 RAS | 解释规格背后的硬件组织 | 白皮书的家族级描述需要再核对具体 SKU 的使能配置 |
| 厂商或设计团队发表的会议、期刊论文 | 微架构、执行模型、数据流、数值路径、芯片实现和实验条件 | 补足产品资料没有展开的底层设计 | 论文原型、首版 silicon 和后续量产 SKU 可能存在版本差异 |
| 官方 ISA、架构参考和编程指南 | 指令语义、数据类型、寄存器或 scratchpad、同步与通信机制 | 确认软件可见的硬件能力 | 指令存在不等于所有 SKU 都以相同吞吐实现；软件接口也不自动证明专用硬件单元 |
| 官方开发文档、SDK 手册和版本说明 | 支持平台、编译目标、运行时接口、library capability 和版本变化 | 核对产品映射、软件可用状态和能力边界 | 编译宏、软件 target 和算子支持不能直接换算成整芯片物理资源 |
| 官方产品页、发布稿、投资者资料和公司公告 | 产品名称、发布日期、定位、供货状态和型号关系 | 固定产品身份及时间状态 | 宣传性比较只有在对象、基线和条件清楚时才采用 |
| 独立逆向分析、拆解和微基准 | cache 层次、访存行为、调度、执行单元和互联行为 | 验证厂商未公开或描述不完整的微架构事实 | 必须保留测试平台、软件版本和推断范围，不能把观察结果写成厂商设计承诺 |
| 系统与性能补充资料 | 加速卡、服务器、机架、Pod、scale-up/scale-out 拓扑和 benchmark 条件 | 解释芯片所处的系统环境和互联边界 | 系统总算力、总带宽、总功耗和吞吐不下放为单芯片指标 |
| 专业媒体、技术访谈和会议演讲 | 设计背景、路线变化、尚未进入正式手册的信息 | 补充设计意图，或帮助定位原始资料 | 有明确采访对象或原始材料链接才用于确认性描述 |
| 第三方数据库、汇总页和论坛 | 型号线索、可能的参数入口和实际设备观察 | 发现资料、交叉检查异常值 | 找不到原始出处时不进入关键规格；论坛日志只代表特定设备和环境 |

## 冗余资料怎么处理

筛选时先看来源能否增加独有信息，再看它是否适合证明当前字段。厂商规格书、数据手册、架构白皮书和原始论文优先；官方开发文档、产品页和发布说明用于补充具体配置与状态；独立微基准只在官方资料没有公开微架构行为时采用。媒体、论坛和汇总页主要用于寻找线索，关键字段仍回到原始资料核对。完整顺序和引用规则见[调研计划](../../调研计划.md)。

| 候选资料情况 | 处理方式 | 进入最小集合的条件 |
|---|---|---|
| 同一文档的镜像、转载或重复下载 | 合并为一个来源，优先保留原始发布地址和可稳定读取的本地文件 | 能回到同一份原文即可 |
| 多个官方页面重复同一组规格 | 保留信息最完整、版本较新且定位最清楚的一份 | 其他页面没有提供独有字段或状态信息 |
| 新闻稿和产品页只有宣传性描述 | 留在候选池，不作为关键规格依据 | 只有出现可定位的产品身份、日期或技术事实时才引用 |
| 第三方汇总表给出参数但没有原始出处 | 不进入正式资料卡 | 找到原始规格书、论文或官方文档后改引原始来源 |
| 板卡、服务器、机架或集群的聚合数据 | 按对象层级隔离，不下放为芯片参数 | 仅在解释 SKU 互联边界时保留必要的系统资料 |
| 来源之间存在数值冲突 | 对照版本、对象和测试条件；无法消除时并列记录 | 每个值都能回到原文，并写清适用条件 |
| 某项信息没有可靠公开资料 | 资料卡写“未公开”或“未找到” | 不用相邻型号或低可信来源补空 |

这套处理保留了不同来源之间的独立信息，也避免同一组规格因转载次数多而获得虚假的证据权重。

## 最小资料库为什么仍然可靠

每张资料卡末尾只列正文实际使用的资料。正文中的数字、日期、规格和实质性技术描述都带有 PDF 页码、表格编号、网页章节或可定位段落。一个来源即使权威，如果没有为该 SKU 提供实际引用，也不会为了增加参考文献数量留在卡片中。

同一份架构资料可以被多个 SKU 复用。例如同一代 Core 或 die 的论文只需要精读一次，但每张 SKU 卡仍分别核对使能资源、内存、功耗和互联配置。这样既减少重复阅读，也保留了产品之间真正不同的部分。

低披露产品没有用推测填满字段。公开资料不足时，资料卡直接记录缺口。这个选择减少了表面上的信息量，却提高了后续分析的可信度：能够比较的字段都有来源，不能比较的字段不会混入相邻型号、板卡或系统数据。

## 汇报时可采用的表述

本轮调研先建立了覆盖 7 家厂商、36 个产品对象的大范围候选资料池。候选清单包含 111 份去重 PDF 和 893 个在线资料入口，当前本地保存 121 份 PDF 与 52 份网页快照。资料类型除了官方规格书和数据手册，还包括架构白皮书、厂商论文、ISA 与开发文档、产品发布资料、独立逆向分析、微基准、系统资料、专业媒体和第三方线索。逐项核对来源、对象层级和引用位置后，36 张资料卡最终使用 233 条参考资料，合并后对应 186 个最小来源目标。

最终资料库保留了完成芯片事实核对所需的最少来源。重复转载、无独有信息的页面、缺少原始出处的参数和层级不匹配的系统数据没有进入正式引用集合。原始候选资料继续保留，既便于追溯，也避免在后续统一分析中反复处理同一批冗余信息。

后续训练与推理差异分析直接使用资料卡及其最小参考资料。原始资料池只在复核争议、补充新字段或检查版本变化时重新启用。
