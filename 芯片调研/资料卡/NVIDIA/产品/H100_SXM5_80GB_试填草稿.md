## 1. 对象边界和结论摘要

本卡只描述搭载 80 GB HBM3（第三代高带宽内存）的 NVIDIA H100 SXM5 模组。它实现 Hopper 架构，板上包含 H100 GPU（图形处理器）与五组 HBM3，并提供第四代 NVLink 芯片互联和 PCIe 5.0 主机接口。白皮书给出的 800 亿个晶体管、814 mm²、TSMC 4N 等数据属于 GH100 裸片的物理实现；HGX H100 的四卡或八卡互联、DGX H100 的整机参数，以及 Grace Hopper 的 CPU与GPU 芯粒互联，都不能回填为本模组的规格。

现有一手资料足以确认 H100 SXM5 的 Tensor Core（张量矩阵运算单元）峰值、非 Tensor Core 计算峰值、HBM3 容量与带宽、L2 与片上存储容量、NVLink/PCIe 带宽，以及 Tensor Memory Accelerator（TMA，张量内存加速器）、线程块集群、分布式共享内存和 DPX 指令的工作边界。公开资料没有把“向量算力”和“标量算力”作为两个独立总峰值发布，也没有给出 L1、共享内存、寄存器或 L2 的官方带宽。未公开的项目保持为空，不能用 H800 实测或相邻型号替代。

## 3. 计算吞吐与数值路径

以下数值均为理论峰值。矩阵稠密值取白皮书 v1.04 的最终时钟版本；稀疏值要求 NVIDIA 支持的结构化稀疏条件，不能与稠密峰值混写。当前数据手册 p.2 的 Tensor Core 表格只列出带稀疏性的较大数值，脚注也明确说明“with sparsity”。

### 3.1 Tensor Core 矩阵路径

| 输入/运算格式 | 已公开累加格式 | 稠密峰值 | 结构化稀疏峰值 | 稳定定位 |
|---|---|---:|---:|---|
| FP8 Tensor Core | FP16 或 FP32 | 1,978.9 TFLOP/s | 3,957.8 TFLOP/s | 白皮书 pp.23至24、39，Table 3 |
| FP16 Tensor Core | FP16 或 FP32 | 989.4 TFLOP/s | 1,978.9 TFLOP/s | 白皮书 pp.20、39，Tables 1、3 |
| BF16 Tensor Core | FP32 | 989.4 TFLOP/s | 1,978.9 TFLOP/s | 白皮书 pp.20、39，Tables 1、3 |
| TF32 Tensor Core | 本次所选来源未单列累加格式 | 494.7 TFLOP/s | 989.4 TFLOP/s | 白皮书 pp.20、39，Tables 1、3 |
| FP64 Tensor Core | 本次所选来源未单列累加格式 | 66.9 TFLOP/s | 不适用/未给稀疏值 | 白皮书 pp.20、39，Tables 1、3 |
| INT8 Tensor Core | 本次所选来源未单列累加格式 | 1,978.9 TOPS | 3,957.8 TOPS | 白皮书 pp.20、39，Tables 1、3 |

FP8 包含 E4M3 与 E5M2 两种编码。白皮书明确写出 FP8 Tensor Core 支持 FP16 和 FP32 累加；Transformer Engine 会在软件与 Hopper Tensor Core 技术配合下按层选择 FP8 或 16 位计算，并完成缩放与重铸。该机制不能据此扩写成一个独立的物理“Transformer 专用核”。

### 3.2 非 Tensor Core 路径

| 路径 | 峰值 | 口径 | 稳定定位 |
|---|---:|---|---|
| FP16 | 133.8 TFLOP/s | CUDA core，非 Tensor | 白皮书 p.39，Table 3 |
| BF16 | 133.8 TFLOP/s | CUDA core，非 Tensor | 白皮书 p.39，Table 3 |
| FP32 | 66.9 TFLOP/s | CUDA core，非 Tensor | 白皮书 p.39，Table 3 |
| FP64 | 33.5 TFLOP/s | CUDA core，非 Tensor | 白皮书 p.39，Table 3 |
| INT32 | 33.5 TOPS | 整数 CUDA core 路径 | 白皮书 pp.39至40，Table 3 |

这些数值是整颗 H100 SXM5 的非矩阵理论峰值。NVIDIA 以 SIMT（单指令、多线程）执行模型描述 CUDA core，没有在所选一手资料中再给出可与其他厂商直接对齐的“独立向量峰值”和“独立标量峰值”。因此本卡把上述数据保留为非 Tensor Core 路径，不擅自改名为向量或标量算力，也不把矩阵、浮点和整数峰值相加成“总算力”。

不同路径使用的峰值时钟也不同：FP8/FP16/BF16/TF32 Tensor Core 表项以 1,830 MHz 为峰值时钟，FP64 Tensor Core 以及 FP32/FP64 非 Tensor 路径以 1,980 MHz 为峰值时钟。白皮书 Table 3 没有把 FP16、BF16 和 INT32 非 Tensor 峰值明确绑定到这两行时钟，因此这三条吞吐的频率条件记为 `not_found`，不能从相邻表项补值。定位为白皮书 p.39，Table 3。

## 6. 特殊机制及其硬件边界

### TMA、线程块集群与分布式共享内存

Hopper 在 SM 中加入 Tensor Memory Accelerator（TMA）。它可以异步搬运全局内存与共享内存之间的一维到五维张量，也能在同一线程块集群的共享内存区域之间复制。地址生成和边界处理由描述符承担，单个线程即可发起，不必让执行线程逐项计算地址。TMA 还支持从共享内存写回全局内存时的 add、min、max 以及按位 and/or 等归约，但这组归约不能泛化为任意 Top-K 或 MoE 路由。定位：白皮书 pp.32至35；Tuning Guide pp.9至10，§1.4.1.2。

线程块集群把多个线程块安排在同一 GPU Processing Cluster（GPC）内，并允许它们同步和访问 Distributed Shared Memory（DSM，分布式共享内存）。远端共享内存支持 load、store 与 atomic；可移植集群上限为 8 个线程块，H100 可显式选择非可移植的 16-block 集群。定位：白皮书 pp.29至31；Tuning Guide pp.10至11，§1.4.1.3。

### DPX 与 Transformer Engine

DPX 是一组面向动态规划的融合指令，包括加法与 min/max 组合以及相应谓词形式，支持 32-bit 整数、打包 16-bit 整数和 half2 等路径；H100 的 16-bit DPX 吞吐上限为 128 operations/cycle/SM。厂商材料称其为指令能力，没有给出一个可独立计数的“DPX 专用核”。定位：白皮书 p.27；Tuning Guide p.11，§1.4.1.4。

Transformer Engine 明确由软件和定制 Hopper Tensor Core 技术组合实现，运行时根据张量统计与缩放因子在 FP8 和 16 位计算之间选择。它是精度管理与矩阵计算机制，不能仅凭“Engine”一词推断为一块独立可枚举的硬件单元。定位：白皮书 pp.44至46；当前数据手册 p.3。

### MoE routing 与 Top-K

在本次选用的 H100 数据手册、Hopper 白皮书和 Hopper Tuning Guide 中，没有找到“专用 MoE routing 模块”或“通用 Top-K 专用模块”的一手证据。该字段状态应为 `not_found`，而不是 `false` 或 `not_applicable`。TMA 归约、DPX 指令和 NVSwitch 集合通信分别解决内存搬运、动态规划和系统互联问题，不能作为上述模块存在的旁证。

### 其他固定功能

H100 包含 7 个 NVDEC（NVIDIA 视频解码）单元和 7 个单核 NVJPG/JPEG 图像解码引擎。定位：当前数据手册 p.2；白皮书 pp.58至59。这些单元对数据预处理有帮助，但不属于矩阵、向量或标量算力。

## 7. 规格版本：3 TB/s 与 3.35 TB/s

2022 年发布期材料给 H100 SXM5 标注 80 GB HBM3、3 TB/s，并注明内存数据率尚未最终确定。白皮书 v1.04 的 Table 3 已列出 2,619 MHz DDR 与 3,352 GB/s，但表内仍保留旧的“not finalized”标签。2024-09-24 生成的当前 H100 数据手册将 H100 SXM 的内存带宽定为 3.35 TB/s。

因此两组数值应建模为时间版本，而不是互相冲突：

| 版本阶段 | 值 | 使用方式 | 定位 |
|---|---:|---|---|
| 发布期/预备规格 | 3 TB/s | 只保留为版本演进证据，不用于当前派生计算 | Hot Chips 34，2022，p.6；Hopper 白皮书 p.11、p.36 的早期表述 |
| v1.04 细化值 | 3,352 GB/s | 白皮书最终时钟版本的精确表值 | Hopper 白皮书 pp.39至40，Table 3 |
| 当前定版数据手册 | 3.35 TB/s | 当前卡片采用值，也是本卡存算比输入 | H100 Datasheet，p.2，“GPU Memory Bandwidth” |
