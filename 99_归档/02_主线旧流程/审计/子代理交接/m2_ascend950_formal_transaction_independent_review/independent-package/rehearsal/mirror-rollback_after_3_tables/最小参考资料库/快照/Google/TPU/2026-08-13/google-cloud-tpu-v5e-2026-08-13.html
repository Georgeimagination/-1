L136: # TPU v5e
L137: 
L138: Note: TPU v5e is supported using Google Kubernetes Engine and the Cloud TPU API. The Cloud TPU API is no longer under active development and will receive bug fixes and security updates only. For more information about TPUs and GKE, see cite57†About TPUs in GKE .
L139: 
L140: This document describes the architecture and supported configurations of Cloud TPU v5e.
L141: TPU v5e supports single and multi-host training and single-host inference. Multi-host inference is supported using cite58†Sax†github.com . For more information, see cite59†Cloud TPU inference .
L142: ## System architecture
L143: 
L144: Each v5e chip contains one TensorCore. Each TensorCore has four matrix-multiply units (MXUs), a vector unit, and a scalar unit.
L145: 
L146: The following diagram illustrates a TPU v5e chip.
L147: 
L148: cite60†Image: Diagram of a v5e chip L149: 
L150: The following table shows the key specifications and their values for v5e.
L151: Specification  | Values
L152: --- | ---
L153: Performance/total cost of ownership (TCO) (expected)  | 0.65x
L154: Peak compute per chip (bf16)  | 197 TFLOPs
L155: Peak compute per chip (Int8)  | 393 TOPs
L156: HBM capacity per chip  | 16 GB
L157: HBM bandwidth per chip  | 800 GiBps
L158: Bidirectional inter-chip interconnect (ICI) bandwidth (per chip)  | 400 GBps
L159: ICI ports per chip  | 4
L160: DRAM per host  | 512 GiB
L161: Chips per host  | 8
L162: TPU Pod size  | 256 chips
L163: Interconnect topology  | 2D torus
L164: BF16 peak compute per Pod  | 50.63 PFLOPs
L165: All-reduce bandwidth per Pod  | 51.2 TB/s
L166: Bisection bandwidth per Pod  | 1.6 TB/s
L167: Per-host NIC configuration  | 2 x 100 Gbps NIC
L168: Data center network bandwidth per Pod  | 6.4 Tbps
L169: Peak compute per Pod  | 100 PetaOps (Int8)
L170: ## Configurations
L171: 
L172: Note: Use the cite61†TPU topology visualizer†tpu-visualizer.uc.r.appspot.com to view 3D renderings of different TPU configurations.
L173: 
L174: Cloud TPU v5e is a combined training and inference (serving) product. Training jobs are optimized for throughput and availability, while serving jobs are optimized for latency. A training job on TPUs provisioned for serving could have lower availability and similarly, a serving job executed on TPUs provisioned for training could have higher latency.
L175: The following 2D slice shapes are supported for v5e:
L176: 
L177: Topology  | Number of TPU chips  | Number of hosts
L178: --- | --- | ---
L179: 1x1  | 1  | 1/8
L180: 2x2  | 4  | 1/2
L181: 2x4  | 8  | 1
L182: 4x4  | 16  | 2
L183: 4x8  | 32  | 4
L184: 8x8  | 64  | 8
L185: 8x16  | 128  | 16
L186: 16x16  | 256  | 32
L187: ### VM types
L188: 
L189: Each TPU VM in a v5e TPU slice contains 1, 4 or 8 chips. In 4-chip and smaller slices, all TPU chips share the same non-uniform memory access (NUMA) node.
L190: 
L191: For 8-chip v5e TPU VMs, CPU-TPU communication will be more efficient within NUMA partitions. For example, in the following figure, `CPU0-Chip0` communication will be faster than `CPU0-Chip4` communication.
L192: 
L193: cite62†Image: NUMA node communication L194: 
L195: The following table shows a comparison of TPU v5e VM types:
L196: VM type  | Machine type  | Number of vCPUs per VM  | RAM (GB) per VM  | Number of NUMA nodes per VM
L197: --- | --- | --- | --- | ---
L198: 1-chip VM  | `ct5lp-hightpu-1t`  | 24  | 48  | 1
L199: 4-chip VM  | `ct5lp-hightpu-4t`  | 112  | 192  | 1
L200: 8-chip VM  | `ct5lp-hightpu-8t`  | 224  | 384  | 2
L201: ### Cloud TPU v5e types for serving
L202: 
L203: Single-host serving is supported for up to 8 v5e chips. The following configurations are supported: 1x1, 2x2 and 2x4 slices. Each slice has 1, 4 and 8 chips respectively.
L204: 
L205: cite63†Image: TPU v5e configurations that support serving: 1x1, 2x2, and 2x4. L206: 
L207: To provision TPUs for a serving job, use one of the following TPU slice sizes in your CLI or API TPU creation request:
L208: Number of TPU chips  | Machine type
L209: --- | ---
L210: `1`  | `ct5lp-hightpu-1t`
L211: `4`  | `ct5lp-hightpu-4t`
L212: `8`  | `ct5lp-hightpu-8t`
L213: 
L214: For more information about managing TPUs, see cite35†Manage TPUs . For more information about the system architecture of Cloud TPU, see cite64†System architecture .
L215: 
L216: Serving on more than 8 v5e chips, also called multi-host serving, is supported using cite58†Sax†github.com . For more information, see cite59†Cloud TPU inference .
L217: ### Cloud TPU v5e types for training
L218: 
L219: Training is supported for up to 256 chips.
L220: 
L221: To provision TPUs for a v5e training job, use one of the following TPU slice sizes in your CLI or API TPU creation request:
L222: 
L223: Number of TPU chips  | Machine type  | Topology
L224: --- | --- | ---
L225: `16`  | `ct5lp-hightpu-4t`  | 4x4
L226: `32`  | `ct5lp-hightpu-4t`  | 4x8
L227: `64`  | `ct5lp-hightpu-4t`  | 8x8
L228: `128`  | `ct5lp-hightpu-4t`  | 8x16
L229: `256`  | `ct5lp-hightpu-4t`  | 16x16
