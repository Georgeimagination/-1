L515: # TPU machines in accelerator-optimized machine family Stay organized with collections Save and categorize content based on your preferences.
L516: 
L517: This document describes the Compute Engine instances in the accelerator-optimized machine family that have Tensor Processing Units (TPUs). TPUs are Google's custom-developed, application-specific integrated circuits (ASICs) that are optimized specifically for artificial intelligence (AI) and machine learning (ML) workloads.
L518: Compute Engine supports the following TPU versions:
L519: 
L520:   * TPU7x
L521:   * TPU v6e
L522:   * TPU v5p
L523: 
L524: Each machine type within a version has a specific topology and a number of TPU chips attached.
L525: ## Fundamentals of TPU architecture
L526: 
L527: Understanding the fundamentals of TPU architecture helps you to choose the TPU version and machine type for your workload.
L528:   * TPU chip: A TPU chip is a specialized accelerator designed by Google for machine learning. Each TPU chip contains one or more TensorCores to handle massive matrix operations. Each TensorCore consists of one or more matrix-multiply units (MXUs), which use a systolic array architecture to perform thousands of multiply-accumulate operations per cycle without constant memory access.
L529: While primarily used for high-speed matrix processing, the TPU chip also includes vector and scalar units for general computation and control flow operations.
L530:   * TPU Pod: A TPU Pod is a contiguous set of TPUs grouped together over a specialized network. The number of TPU chips in a TPU Pod is dependent on the TPU version.
L531: 
L532:   * TPU VM: A TPU VM is a Linux virtual machine that runs on a TPU host and has access to the underlying TPUs. You can connect directly to TPU VMs using SSH. You have root access to the VM, so you can run arbitrary code. You can access compiler and runtime debug logs and error messages.
L533:   * TPU slice: A logical group of interconnected TPU chips, accessed through one or more TPU VMs. Slices have one of the following scopes:
L534: 
L535:     * Single-host slice: A slice consisting of one host machine. In general, this maps to one TPU VM.
L536:     * Multi-host slice: A slice consisting of multiple TPU VMs interconnected using a high-speed inter-chip interconnect (ICI).
L537:   * TPU cube: A 4x4x4 topology of interconnected TPU chips. This is only applicable to 3D topologies.
L538:   * SparseCore: SparseCores are dataflow processors that accelerate models using sparse operations. A primary use case is accelerating recommendation models, which rely heavily on embeddings.
L539: 
L540:   * TPU versions: The exact architecture of a TPU chip depends on the TPU version that you use. Each TPU version also supports different slice sizes and configurations.
L541: 
L542: For information about how TPUs work, see cite57†TPU architecture document in the Cloud TPU documentation.
L543: ## Recommended TPU versions by workload types
L544: 
L545: TPU version  | Primary workload types
L546: --- | ---
L547: TPU7x (Ironwood)  |
L548: 
L549:   * Large-scale dense and Mixture-of-Experts (MoE) models
L550:   * Intensive pre-training for massive foundation models
L551:   * Sampling and decode-heavy inference
L552: TPU v6e (Trillium)  |
L553: 
L554:   * Training & fine-tuning (Transformers, CNNs)
L555:   * Large-scale inference (Gemma 2, Llama, Diffusion models)
L556:   * Recommendation engines and personalization (using SparseCore)

L558:   * Highest performance for large-scale foundation model training
L559:   * Massive-scale multi-modal AI training
L560:   * Embedding-dense workloads like large recommendation systems
L561: ## Consumption options
L562: 
L563: To optimize resource utilization and cost while balancing workload performance, Compute Engine supports the following TPU consumption options:
L564:   * On-demand: to consume TPUs without arranging capacity in advance. Before requesting resources, you must have enough cite58†on-demand quota for the specific type and quantity of TPU VMs. On-demand is the most flexible consumption option; however, there is no guarantee that enough on-demand resources will be available to fulfill your request.
L565:   * Spot VMs: to provision Spot VMs, you can get significant discounts, but Spot VMs can be preempted at any time, with a 30-second warning. For more information, see cite59†About Spot VMs .
L566: 
L567:   * Flex-start: to provision Flex-start VMs for up to seven days, with Compute Engine automatically allocating the hardware on a best-effort basis based on availability. For more information, see cite60†About Flex-start VMs .
L568:   * Future reservation: to request a future reservation for one year or longer. For more information, see cite61†Request a future reservation for one year or longer in the Cloud TPU documentation.
L569: 
L570:   * Future reservation in calendar mode: to provision TPU resources for up to 90 days, for a specified time period. For more information, see cite62†About future reservation requests in calendar mode .
L571: 
L572: On-demand is the default consumption model for TPUs if you don't specify another option.
L573: For information about the underlying provisioning model that enables the consumption option, see cite63†About VM provisioning models .

L640: ## TPU machine types
L641: 
L642: The following sections describe the machine types available for each TPU version.
L643: ### TPU7x (Ironwood)
L644: 
L645: Each TPU7x virtual machine (VM) contains 4 TPU chips. All TPU7x slices use full-host, 4-chip VMs.
L646: 
L647: Each TPU7x chip contains two TensorCores and four SparseCores.
L648: 
L649: The Ironwood programming model lets you access two TPU devices instead of a single logical core architecture used in previous generations. For more information, see cite71†Dual-chiplet architecture in the Cloud TPU documentation.

L655: ### TPU v6e (Trillium)
L656: 
L657: Each TPU v6e VM can contain 1, 4, or 8 TPU chips. 4-chip and smaller slices have the same non-uniform memory access (NUMA) node.
L658: 
L659: v6e slices are created using half-host VMs, each with 4 TPU chips, except for the following:
L660:   * `ct6e-standard-1t` with only a single TPU chip is primarily intended for testing.
L661:   * `ct6e-standard-8t` is a full-host VM that has been optimized for an inference use case, allowing all 8 TPU chips that are attached to a single VM to be used in a single serving workload.

L668: ### TPU v5p
L669: 
L670: A TPU v5p Pod is composed of 8960 TPU chips interconnected with reconfigurable high-speed links. TPU v5p's flexible networking lets you connect the TPU chips in a same-sized slice in multiple ways. Single slice training is supported for up to 6144 TPU chips.

L676: ## TPU topology
L677: 
L678: The topology defines the physical arrangement of TPUs within a TPU slice. Depending on the TPU version, the topology is two- or three-dimensional. You can identify the number of TPU chips in a slice by calculating the product of each size in the topology. For example:
L679: 
L680:   * The `tpu7x-standard-4t` machine type with a `2x2x2` topology is an 8-chip multi-host TPU7x slice.
