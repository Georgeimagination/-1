L136: # TPU v6e
L137: 
L138: This document describes the architecture and supported configurations of Cloud TPU v6e (Trillium). On all technical surfaces, such as the API and logs, and throughout this document, Trillium will be referred to as v6e.
L139: 
L140: With a 256-chip footprint per Pod, v6e shares many similarities with cite57†v5e . This system is optimized for transformer, text-to-image, and convolutional neural network (CNN) training, fine-tuning, and serving.
L141: ## System architecture
L142: 
L143: Each v6e chip contains one TensorCore. Each TensorCore has 2 matrix-multiply units (MXU), a vector unit, and a scalar unit. The following table shows the key specifications and their values for TPU v6e.
L144: Specification  | Values
L145: --- | ---
L146: Performance/total cost of ownership (TCO) (expected)  | 1
L147: Peak compute per chip (bf16)  | 918 TFLOPs
L148: Peak compute per chip (Int8)  | 1836 TOPs
L149: HBM capacity per chip  | 32 GB
L150: HBM bandwidth per chip  | 1638 GBps
L151: Bidirectional inter-chip interconnect (ICI) bandwidth (per chip)  | 800 GBps
L152: ICI ports per chip  | 4
L153: DRAM per host  | 1536 GiB
L154: Chips per host  | 8
L155: TPU Pod size  | 256 chips
L156: Interconnect topology  | 2D torus
L157: BF16 peak compute per Pod  | 234.9 PFLOPs
L158: All-reduce bandwidth per Pod  | 102.4 TB/s
L159: Bisection bandwidth per Pod  | 3.2 TB/s
L160: Per-host NIC configuration  | 4 x 200 Gbps NIC
L161: Data center network bandwidth per Pod  | 25.6 Tbps
L162: Special features  | cite58†SparseCore L163: ## Supported configurations
L164: 
L165: Note: Use the cite59†TPU topology visualizer†tpu-visualizer.uc.r.appspot.com to view 3D renderings of different TPU configurations.
L166: 
L167: The following table shows the 2D slice shapes that are supported for v6e:
L168: Topology  | TPU chips  | Hosts  | VMs  | Machine type  | Scope
L169: --- | --- | --- | --- | --- | ---
L170: 1x1  | 1  | 1/8  | 1  | `ct6e-standard-1t`  | Sub-host
L171: 2x2  | 4  | 1/2  | 1  | `ct6e-standard-4t`  | Sub-host
L172: 2x4  | 8  | 1  | 1  | `ct6e-standard-8t`  | Single-host
L173: 2x4  | 8  | 1  | 2  | `ct6e-standard-4t`  | Multi-host
L174: 4x4  | 16  | 2  | 4  | `ct6e-standard-4t`  | Multi-host
L175: 4x8  | 32  | 4  | 8  | `ct6e-standard-4t`  | Multi-host
L176: 8x8  | 64  | 8  | 16  | `ct6e-standard-4t`  | Multi-host
L177: 8x16  | 128  | 16  | 32  | `ct6e-standard-4t`  | Multi-host
L178: 16x16  | 256  | 32  | 64  | `ct6e-standard-4t`  | Multi-host
L179: Note: The 8-chip (2x4) configuration attached to 2 VMs is only supported when using the GKE API.
L180: Slices with 8 chips (`v6e-8`) attached to a single VM are optimized for inference, allowing all 8 chips to be used in a single serving workload. You can perform multi-host inference using Pathways on Cloud. For more information, see cite60†Perform multihost inference using Pathways .
L181: 
L182: For information about the number of VMs for each topology, see cite61†VM Types .
L183: ### VM types
L184: 
L185: Each TPU v6e VM can contain 1, 4, or 8 chips. 4-chip and smaller slices have the same non-uniform memory access (NUMA) node. For more information about NUMA nodes, see cite62†Non-uniform memory access†en.wikipedia.org on Wikipedia.
L186: 
L187: cite63†Image: Diagram of a v6e host L188: 
L189: v6e slices are created using half-host VMs, each with 4 TPU chips. There are two exceptions to this rule:
L190:   * `v6e-1`: A VM with only a single chip, primarily intended for testing
L191:   * `v6e-8`: A full-host VM that has been optimized for an inference use case with all 8 chips attached to a single VM.
L192: 
L193: The following table shows a comparison of TPU v6e VM types:
L194: VM type  | Number of vCPUs per VM  | RAM (GB) per VM  | Number of NUMA nodes per VM
L195: --- | --- | --- | ---
L196: 1-chip VM  | 44  | 176  | 1
L197: 4-chip VM  | 180  | 720  | 1
L198: 8-chip VM  | 360  | 1440  | 2
L199: Note: We don't recommend using a full-host VM (`v6e-8` with one VM) for dual networks due to performance impacts.
