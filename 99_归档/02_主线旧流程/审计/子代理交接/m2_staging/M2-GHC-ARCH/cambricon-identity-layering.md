# 寒武纪架构与软件标识分层判断

> 状态：阶段性判断，供总控合并前复核。证据截止日为 2026-08-12。本文件不新增正式对象。

## 判断

现有一手证据只支持两个物理架构名：思元590 的 `MLUarch05`，以及思元370 官方产品页的 `MLUarch03`。候选表中的 BANG v2.0、v3.0、v5.0 暂不能按同名规则升级成物理架构对象。BANG 是软件工具链可见的版本或目标层；没有可读的版本化官方正文把它与 `MLUarchNN` 一一等同，就不能让两套名称互相继承规格。

| 标识 | 当前语义层 | 可确认内容 | 不能确认的内容 | 本包处置 |
|---|---|---|---|---|
| `MLUarch05` | 厂商公开物理架构名 | 2022 WAIC 原厂页面直接说思元590采用该架构 | 与 BANG v5.0、`compute_50`、`mtp_592` 或数值 `592` 等价 | 复用正式 `OBJ-CAMBRICON-MLU590-ARCH` 与既有事实，不重复新增 |
| BANG v5.0 | 待核软件架构/工具链代际 | 搜索索引提示它与 MLU570/590 同组出现 | 与 `MLUarch05` 等价；可以承接物理规格 | 保留候选 `CAND-CAMBRICON-ARCH-BANG-V5`，`needs_resolution`，不建正式对象 |
| `compute_50` | 软件编译目标标识 | 现有不可读 CNToolkit 入口的索引线索 | 物理架构名称、芯片数量或核心规模 | 只留软件标识记录，不建对象 |
| `mtp_592` | 软件目标字符串 | 固定 MLU-OPS 提交将 `--mlu590` 映射到 `mtp_592;` | `{18}` 的语法、物理核心数、容量或与 `MLUarch05` 等价 | 只留软件标识记录，不建对象 |
| `__BANG_ARCH__=592` | 编译期宏 | 固定提交的帮助文本直接把 `--mlu590` 写成该宏值 | “第 592 代”物理架构；NRAM/WRAM/SRAM 物理容量 | 复用 M1 芯片级软件目标事实；不创建架构事实 |
| `MLUarch03` | 厂商公开物理架构名 | 思元370官方页直接给出 `MLUarch03`，并描述 Supercharger 与多算子硬件融合 | 与 BANG v3.0 等价 | 本包只记录反向身份证据；不越权新增正式对象 |
| BANG v3.0 | 候选软件代际名 | 历史候选表把它与 MLU370 相邻记录 | 官方可读正文中的正式物理架构名；与 `MLUarch03` 等价 | 不建正式对象；建议将后续身份检索改为证明 BANG v3.0 与 MLUarch03 的关系，而不是默认等价 |
| BANG v2.0 | 候选软件代际名 | 历史候选表把它与 MLU290 相邻记录；MLU290-M5 官方产品身份可读 | BANG v2.0 的正式定义、物理架构名称或与思元290的一手映射 | 不建正式对象；保持 `needs_resolution` |

## 访问限制

CNToolkit 3.8.4 正文在 2026-08-12 返回远端 HTTP 401。此前项目记录还见到远端 400 timeout。它是远端访问限制，不是沙箱、审批、模型能力或本地解析失败。搜索结果摘要只用于发现入口，没有进入正式事实链。

GitHub 官方组织 API 的公开匿名查询本轮返回速率限制；这是远端服务限流。固定 MLU-OPS 文件仍可通过已知提交的 raw 入口读取，因此不影响 `--mlu590` 与软件宏的复核，但降低了广泛枚举其他仓库的效率。

## 解除条件

BANG v2/v3/v5 只有在拿到可读取、版本固定的一手文档，并由同一段正文同时写出 BANG 版本与对应芯片或 `MLUarchNN` 名称后，才具备建立正式关系的最低条件。若文档只列编译目标或支持矩阵，仍应建软件兼容关系，而不是物理架构同义关系。
