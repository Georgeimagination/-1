# M2 第三波三包组合正式事务准备包

## 状态

`ready_for_independent_review`

本目录把 MI455X、MI350P 和 Ascend 950 三个已经冻结的事实包合成一次原子事务。这里的“原子事务”是指三包共用一个候选、一个事务锁和一本事务日志（journal）：要么 1,057 行生命周期写入和 15 个文件载荷全部成功，要么把本次已经登记的改动按相反顺序全部撤销。准备包没有修改正式库，也不构成正式执行授权。

## 冻结边界

三包都绑定同一个正式 32 表基线 `f1520907d54e406e7d82f591e3799f07f569218aff0c321ac3b836b6c649da10`。MI455X、MI350P 和 Ascend 950 的数据签字分别为 245、274 和 553 行；对应的事务级独立复核签字都已逐项核对为 `accept / true`。精确路径和 SHA-256（安全哈希算法）记录在 `upstream-bindings.csv`，依赖状态记录在 `input-dependencies.csv`。

组合写集包含 1,057 个生命周期主键、15 个新文件目标和 11 个只读保护项（guard）。跨包生命周期主键交集和载荷路径交集均为 0。三包共同使用 19 张 CSV 表，但这些共享容器中的主键不重叠；另有 1 张表只由 Ascend 950 写入，因此总写表数是 20。`数据/objects.csv` 与 `数据/object-relations.csv` 只作保护表，不在提交写集内。

组合候选从 f152 一次生成，硬门校验通过 125,619 项，32 表聚合哈希为 `5f62191bfc737535802cd6e0524b1fdf7a742ca36300db11b5a9233d4540052a`。20 张写表的逐表后哈希见 `expected-candidate-20-table-posthashes.csv`。

## 演练结果

正向演练完成 20 张表替换和 15 个文件复制，事务日志有 72 行；候选和提交后的校验均为 125,619 项。第 3 张表提交后注入故障时，脚本逆序恢复 3 张表。第 2 个载荷提交后注入故障时，脚本先逆序删除 2 个载荷，再逆序恢复 20 张表。两种故障场景结束后，镜像都回到 f152。

负向测试共 12 例。六个通用门覆盖默认正式模式拒绝、错误令牌、待独立复核模板、错误镜像标记、预存载荷目标和错误合并前哈希；另六例分别验证三包中任一事务签字缺失或哈希错误都会在写入前被拒绝。所有用例都以非零退出码命中预期错误，正式库前后均为 f152，15 个正式载荷目标始终不存在。

## 独立复核入口

复核者先读 `VALIDATION-RECORD.md` 和 `EXECUTION-ROLLBACK.md`，再核对 `authorized-write-set.csv`、`new-file-targets.csv`、`no-write-guards.csv`、`formal-backup-manifest-template.csv`、三场事务日志和 12 项负向门证据。正式执行前还必须在正式根之外建立 24 项精确备份，并由不同代理另建一份 `accept / true` 外部签字，绑定冻结后的 `manifest.csv`、包聚合哈希、三个脚本、上游签字、f152 基线、候选后哈希和授权令牌。

`transaction-review-signoff-template.csv` 仍为 `pending / false`。执行器在 `TargetRoot` 等于正式根时默认硬拒绝；准备者没有签字，也没有创建正式授权标记。正式写入次数为 0。
