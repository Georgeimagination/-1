## 事务要求

当前 486 行签字给出了 20 张写表的预合并哈希，但没有给出逐表合并后哈希。签字文件本身也不包含完整来源行或未改动的旧行。因此，不能只凭这一份 CSV 在丢失正式基线后还原 20 张完整结果；必须同时保留当前正式表、签字引用的来源文件、动作顺序和固定的 CSV 序列化规则。

正式执行器应先在同卷受控临时区生成完整结果，运行默认 `gate` 校验并记录 20 张合并后哈希。全部预检通过后，再逐文件替换正式表。文件系统不能一次原子替换 20 张表和 15 个新增文件，所以事务必须持有独占锁、逐项写提交日志，并在任何失败后自动按逆序恢复。现有 `Invoke-AwsPackageMerge.ps1` 只允许隔离目标，不能直接写正式根；新的正式事务实现必须证明其行级语义与该脚本一致。
