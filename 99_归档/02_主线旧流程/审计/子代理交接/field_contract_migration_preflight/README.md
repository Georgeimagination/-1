## 严格执行顺序

1. 冻结修正版，记录候选文件哈希，由独立复核者对这个精确版本给出 `accept`。
2. 在没有其他正式写入任务运行时，带 `-IndependentReviewPath` 执行本目录的预检脚本。脚本退出码必须为 0。
3. 新建独立备份目录，复制四个允许写入文件，再逐文件核对旧哈希、字节数和换行格式。备份未验证前不能写正式库。
4. 按候选文件逐字节替换 `schema-columns.csv`、`fields.csv`、`field-requirements.csv` 和校验器。每次替换后立即核对候选哈希和字节格式；不要在正式文件里临时计算或手改单元格。
5. 先显式运行校验器的 `audit`（审计输出）模式，再运行 `gate`（硬门）模式，最后不传该参数确认默认就是 `gate`。三次都通过后，才进入项目文档和验收记录更新。

## 回滚门

写第一个正式字节以前，只要基线哈希、候选哈希、独立签字、备份或预检有一项不符，就结束本次执行，不需要回滚。

正式写入开始后，只要候选哈希、编码、换行、差异数量、`audit`、`gate` 或默认门有一项不符，应停止后续动作，并从同一备份完整恢复四个文件。恢复后逐字节核对四个旧哈希，并重跑旧校验器，预期恢复到 93,378 项检查。不能只恢复报错的单个文件，因为 schema、字段表、字段要求表和校验器属于同一个迁移单元。

如果 13 个禁止写入文件或只读输入探针中的任何文件发生变化，四文件备份不能恢复该并发变化。此时应保留现场和备份，报告发生变化的路径，不得声称已经恢复到原基线。
