## 893 与 892 的差异

`网页与在线资料.csv` 有 914 行，其中 v4 来源 588 行，codex-v3 来源 326 行。两边有 21 个完全相同的 URL，因此按大小写敏感的原始字符串统计是 893 个：

`588 + 326 - 21 = 893`

按 PowerShell 默认的大小写不敏感方式去重时，结果会变成 892。多出来的合并只涉及同一篇文档的两个 DOI 入口：

- `https://doi.org/10.1109/MM.2021.3113475`
- `https://doi.org/10.1109/mm.2021.3113475`

这两行都来自 codex-v3，标题都是 `Evolution of the Graphics Processing Unit`。脚本的 `normalize_url()` 只把协议和主机名转为小写，路径仍区分大小写，所以保留了这两个 DOI 字符串。`汇总统计.json` 中的 893 与脚本当前算法一致；892 是大小写不敏感的字符串数。两个数字代表不同的规范化规则，不能继续都叫“合并 URL 数”。

修复时不应把所有网站的路径都转成小写，因为普通网页路径可能区分大小写。可针对 `doi.org` 单独规范化 DOI 路径，并把以下口径分别记录：项目内 URL 行数、跨项目大小写敏感 URL 数、规范化访问入口数、来源家族数。最小参考资料库最终需要的是来源家族和事实覆盖，不是 URL 字符串数。

## 收集脚本在 Windows 上不能复现

直接使用配置好的 Python 运行 `scripts/collect_references.py`，脚本在读取下列旧路径时终止：

`\Users\gxli\Documents\Workspace\2026projects\调研-训练推理芯片调研-codex-v3\.tmp\paper_inventory_final.json`

失败类型是 `FileNotFoundError`。原因是脚本固定写入原作者的 macOS 工作区路径；这不是沙箱拦截，也不是审批失败。

即使把根路径手动改成当前 Windows 路径，`pdf_info()` 仍有兼容问题。本机的 `pdfinfo` 命令入口是 `.cmd` 包装器，Python 以 `subprocess.run(["pdfinfo", ...])`、`shell=False` 调用时返回 `PermissionError: [WinError 5]`。直接调用打包环境中的 `pdfinfo.exe` 可以工作，当前 Python 也已安装 `pypdf`。修复脚本时可优先用 `pypdf` 获取页数，必要时再调用显式配置的 `pdfinfo.exe`，并保留警告文本。

脚本还有四项会影响可重复性：

1. 它依赖 codex-v3 的 `.tmp/paper_inventory_final.json`，这是临时目录中的输入，没有在输出中记录输入哈希。
2. Windows 上 `str(Path)` 会写出反斜杠，而现有清单是在 macOS 上生成的正斜杠路径。重新生成后即使内容相同，CSV 也会发生机械差异。
3. CSV 和 JSON 直接覆盖，没有只读检查模式、临时文件校验和原子替换；脚本中途失败可能留下部分输出。
4. URL 提取不区分文献链接、页面图片、跟踪参数和语言镜像，解析状态只看进程退出码，也不记录生成器版本、运行时间或输入指纹。

## 可执行的修复方案

建议把收集、校验和正式重建分开。脚本默认执行只读检查，只有显式传入 `--rebuild` 才复制文件和替换清单。路径通过参数传入，例如 `--project-v4`、`--project-codex` 和 `--dest-root`；没有参数时，只能从脚本所在目录推导相邻目录，不能回退到个人绝对路径。

重建前先验证三个根目录和四个必要输入是否存在，并固定这些输入的哈希。序列化路径统一使用 `Path.as_posix()`。PDF 校验至少记录 `exists`、`size_match`、`sha256_match`、`page_match`、`encrypted`、`parse_warning` 和 `parser_version`。写出新文件时先写到同目录临时文件，读回检查行数、表头、唯一键和外键，再执行原子替换。

URL 层需要同时保留“访问入口”和“来源家族”。通用规范化只处理协议、主机名、片段和明确的跟踪参数；DOI、arXiv 和语言镜像采用站点专用规则。图片、附件和压缩包保留为家族的附属入口，不计作独立来源。来源家族形成后再由资料卡事实覆盖决定是否进入最小集，不能仅凭 URL 相似度判定重复。

修复后建议生成以下审计文件，由总控决定最终文件名和位置：

| 输出 | 用途 |
|---|---|
| `pdf-validation.csv` | 逐文件记录存在性、哈希、大小、页数、加密和解析警告 |
| `url-validation.csv` | 记录原 URL、规范化入口、主机、查询参数、资源类型和联网状态 |
| `source-family-candidates.csv` | 记录 DOI、arXiv、官方文档号、镜像和版本家族候选 |
| `audit-run.json` | 记录脚本版本、Python 与解析器版本、输入哈希、运行时间、统计口径和输出哈希 |
| `资料池审计.md` | 面向人工复核，解释异常、缺口和本次采用的计数口径 |

联网检查应另行执行，并记录最终跳转地址、HTTP 状态、获取时间和失败类型。403、429、登录页和付费墙应标为受限或限流，不能直接判为失效；图片入口也不能用网页正文规则检测。本次没有联网运行，因此没有对 914 个入口作存活结论。
