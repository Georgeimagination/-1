# AWS 四代物理对象事实包：正式合并事务准备

状态：`ready_for_independent_review`

本目录冻结一套一次性合并事务，供独立复核者在镜像中检查 AWS Trainium、Inferentia 四代物理对象事实包。它不是正式执行许可；本任务没有改动正式 CSV、资料卡或网页快照，也没有创建正式备份目录。

## 安全门

正式根默认拒绝。只有同时满足以下条件，脚本才会进入候选生成：显式提供 `-AllowFormalRoot` 和精确授权 token；提供独立事务复核的单行签字及其实际 SHA-256；签字精确绑定三份脚本、冻结 manifest、package aggregate、两份既有 AWS 签字、正式基线和 token；外部 `BackupRoot` 已有完整 25 项备份清单和授权 marker。上述内容全部通过后，正式模式的候选、临时备份、锁和结果仍位于正式根之外。

提交临界点会再次核对完整 32 表 aggregate、9 个守卫、20 张待写表和 15 个不存在目标。提交按文件登记 journal；失败时严格按实际提交顺序的逆序回滚。新 payload 只有在“本事务已登记创建”且当前哈希仍等于签字预期时才会删除。守卫表若出现漂移，事务报警并拒绝静默覆盖。

## 当前验证结论

冻结脚本已通过 PowerShell 语法解析、17 项静态合同检查、正式根默认拒绝测试和只读预检。当前正式库校验为 `97,920` 项通过；32 张正式表与签字基线逐表一致，15 个正式 payload 目标仍为 0，锁和事务临时文件为 0。

较早版本已完成三场景镜像演练：正向 477 次授权写入、9 个守卫、候选与写后各 `106160` 项检查；替换 3 张表后失败可回滚；替换 20 张表并复制 4 个 payload 后失败也可回滚。收口阶段按总控要求停止长跑，因此这些结果不能代替对当前冻结脚本的独立重跑。独立复核者必须重新执行镜像正向和两个故障注入场景，确认通过后另行生成外部事务签字。

## 阅读顺序

先看 `VALIDATION-RECORD.md` 了解已验证和待复跑边界，再看 `EXECUTION-ROLLBACK.md` 核对备份、授权、执行与恢复合同。三份脚本分别负责只读预检、事务执行和镜像演练。`transaction-review-signoff-template.csv` 只是不可授权的表头模板；复核者应在冻结包外生成最终单行签字，不能修改本目录后沿用原 manifest。
