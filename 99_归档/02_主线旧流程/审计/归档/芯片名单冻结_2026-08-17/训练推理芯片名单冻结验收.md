## 时间边界和纳入门

主样本按 2022-01-01 至 2026-08-17 处理。早于 2022 年的对象只有在它能解释主样本代际、共享裸片或现役产品关系时才选作历史锚点。厂商已正式命名且公开资料足以开展架构研究的芯片，即使仍处于路线图、预览或 `coming soon` 状态，也进入主样本；所有未来定值必须保留 `projected` 或 `pending_verification` 条件。只有系列名、架构代号、市场模组名，或者仍不能落到 `die/package` 的对象，不进入芯片计数。

训练或推理相关性只用于判断对象是否属于研究范围，不表示性能高低，也不在名单冻结阶段展开架构比较。产品身份已有官方一手入口闭合后即停止搜索；本轮没有扩展到媒体检索、规格抽取、事实卡、模组、卡、实例、服务器、机架或 Pod（芯片集群）工作包。

## 计数方法

die 指厂商稳定命名的计算裸片；package 指能与外层板卡或模组分开的单颗芯片封装，封装内部可以有多颗裸片。共享裸片设计只列一行：同一裸片在多个产品中出现，或者一个封装里装入 2、6、8 颗相同裸片，都不会把对象数乘大。厂商正式命名的不同封装产品可以各列一行，但必须同时标明共享裸片关系。

别名、代际补写、文档修订和容量配置不增加计数。例如 Trainium 与 Trainium1 归为同一个对象，Trillium 与 TPU v6e 归为同一个对象，GroqChip 的 v1.5 和 v1.7 产品简报也不代表两代芯片。板卡、PCIe（Peripheral Component Interconnect Express，高速外设互连）卡、OAM（OCP Accelerator Module，开放计算项目加速模组）、EAM（Enterprise Accelerator Module，企业加速模组）、云实例、服务器和机架一律不计。

CSV 的 `silicon_design_group` 用来汇总底层 AI 计算硅设计，不代替对象行。当前 49 个计数对象归入 45 个共享硅设计组。MI455X GPU package 与 CDNA 5 XCD 共用一组；MI430X 是否与 MI455X 完全复用计算裸片仍缺少足够的一手证据，因此暂时单列设计组，后续只能依据官方资料合并。

Ascend 950 是最容易误读的例子：名单保留 1 个 Ascend 950 Die，以及 950PR、950DT 两个封装变体，所以对象行数为 3；按底层计算裸片设计汇总时仍只有 1 个共享硅设计。NVIDIA Blackwell 和 Rubin 的两个内部 reticle（光刻版曝光尺寸）级裸片没有稳定独立产品名，分别统一计为一个 GPU package，不另建匿名裸片行。AMD 的 GCD（Graphics Compute Die，图形/计算裸片）与 XCD（Accelerator Complex Die，加速器复合裸片）按共享计算裸片设计计数，IOD（I/O Die，输入输出裸片）等非 AI 计算裸片不进入本名单。

## 观察、待决与排除边界

当前 4 个路线图观察对象是 NVIDIA Rubin Ultra GPU、LP35、LP40，以及 Feynman 世代未命名 GPU。前三者已经由 NVIDIA 正式命名，但尚未给出足以稳定建立 `die/package` 对象的计算单元、存储和封装规格；Feynman 只是正式世代名，厂商只确认该世代将有新 GPU，尚未公布 GPU SKU。AMD MI500/CDNA 6 仍只有系列或架构路线图，也不按芯片对象计数。

五个待决对象是 NVIDIA L2、H20 BFX、Cambricon MLU580、AMD MI308X 和 MI440X。L2 没有底层 die/package 映射；H20 BFX 的官方架构归类互相冲突；MLU580 目前只有软件新增硬件支持的表述；MI308X 和 MI440X 尚未把单芯片封装与外层加速器形态分清。这些对象没有被遗漏，待官方资料闭合后再转入计数。

独立复核确认 GB203 已由 RTX PRO 4500 Blackwell Server Edition 的官方数据中心、边缘和云推理身份闭合，因此纳入主样本。19 个排除对象继续按既定边界处理：NVIDIA GH200 是 Grace CPU 与 GH100 GPU 的多处理器模组，B100、B200、B300 是 SXM（NVIDIA 服务器加速模组形态）模组；Google TPU v1、v2 超出时间边界且不承担本轮历史锚点；AWS Inferentia3、Groq 2 与 Cambricon MLU690 截止日没有通过官方命名门。

AMD 的 MI210 与 MI350P 是 PCIe 卡；MI250、MI250X、MI300X、MI325X、MI350X、MI355X 是 OAM 市场对象；MI455X 公开资料区分内层多芯片 GPU package、EAM 模组和由四颗 MI455X GPU 组成的 compute tray，但没有公开每个 EAM 内的 package 数量；MI500 目前只有系列级路线图。既有正式或历史数据全部保留，非芯片对象不进入芯片计数。MI200 GCD、CDNA 3/4/5 XCD 已承接这些产品中可稳定命名的计算裸片，不再从外层市场名推造匿名封装。

## 仍需复核的边界

MI455X GPU package 的边界已经关闭。AMD 官方资料明确区分内层多芯片 GPU package 与外层 EAM，并公开 8 颗 XCD、256 WGP、HBM4 和封装互连信息，因此该 package 进入计数；MI455X EAM 模组仍然排除。

第二项是其他 AMD 市场型号的处理。MI250/250X、MI300X/325X、MI350X/355X 的官方资料能证明多裸片组成，却没有同样清楚地给出可与 OAM 分开的稳定内层产品名。候选稿采用保守口径，只计共享 GCD/XCD，不另造同名 package。MI300A 例外，因为官方明确它是单一 SH5 插槽封装，不是 OAM 或 PCIe 卡。

第三项是公开信息仍会变化的未来芯片。Rubin CPX、TPU 8t/8i、Trainium4、Ascend 960/970 和 MI430X 已进入研究范围，但资料卡必须把工程预测、路线图目标和稳定规格分开。Rubin Ultra、MLU580 和 MI440X 仍保留观察或待决状态，不能从同系列芯片类推缺失参数。

第四项是 NVIDIA 的细边界。Blackwell Ultra 作为正式命名的独立 GPU package 与 GB100 Blackwell package 分开计数，但不声称二者必然使用不同底层裸片。NVIDIA Groq 3 LP30 的官方资料已明确称其为 chip；候选稿用 package 保守承接其单器件物理层级，不把 LPX 托盘或机架计入。当前建议维持这两项处理。
