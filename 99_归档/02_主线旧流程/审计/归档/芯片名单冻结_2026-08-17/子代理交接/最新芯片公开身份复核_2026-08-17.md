# 最新训练与推理芯片公开身份复核（截至 2026-08-17）

## 任务与口径

本次复核只回答范围问题：七家厂商已经正式公开的最新训练或推理芯片中，哪些应进入后续架构研究。判断口径统一为：厂商已经正式命名，物理芯片身份能够落到裸片或单颗芯片封装，并且一手资料已经给出足以开展架构研究的结构或规格信息。芯片是否已经一般可用，只记录产品状态，不作为排除条件。

这里的“信息足够”不要求完整数据手册。只要厂商已经明确芯片用途，并公开了可用于代际比较的计算、存储、数据格式或互联信息，就可以先纳入研究；资料仍处于设计目标阶段的对象，必须在资料卡中标为 preliminary，不能把目标值写成已实现规格。只有系列名、系统名或加速卡名，没有稳定芯片名和可核规格的对象继续观察。

复核以 `审计/训练推理芯片名单冻结.csv` 中的 41 个计数对象为基线。检索只采用厂商官网、官方技术文档、官方博客、官方演讲实录和厂商正式论文，没有用媒体报道补足芯片身份。

## 范围调整结论

按上述口径，原来 7 个观察对象都可以进入研究，即 NVIDIA Rubin CPX、Google TPU 8t、Google TPU 8i、AWS Trainium4、Huawei Ascend 960、Huawei Ascend 970 和 AMD Instinct MI430X；AMD Instinct MI455X 内层 GPU package 也可以结束用户裁决，进入计数。调整后的建议基数为 49 个芯片对象。

其中 Rubin CPX、TPU 8t、TPU 8i、Ascend 960、MI430X 和 MI455X GPU package 已经有较完整的芯片级结构或绝对规格，可以直接开展架构研究。Trainium4 和 Ascend 970 的证据弱一档，但都不再只是名称：AWS 给出了 FP4、FP8、内存带宽的代际倍率和 NVLink Fusion，华为给出了 FP4、FP8、互联带宽以及内存带宽的规划值。按用户要求的宽口径，它们也应纳入，不过结论必须明确限定为设计期目标。

49 个对象的资料成熟度并不相同。研究范围可以放宽到已公开设计目标的芯片，但后续资料卡仍要把“正式规格”“设计目标”和“路线图方向”分开。

## 七家厂商截至截止日的遗漏检查

NVIDIA 需要提升 Rubin CPX，并新增 Rubin Ultra、LP35、Feynman GPU 和 LP40 观察项。Google 的最新明确对象就是 TPU 8t 与 TPU 8i，两者都应纳入。AWS 应纳入 Trainium4，没有发现更晚且身份稳定的新自研训练或推理芯片。Groq 官网没有发现第一代 GroqChip 之外的新一代、已正式命名且具备芯片级规格的独立对象；NVIDIA Groq 3 LP30 已在现表计数。

寒武纪公开软件已经识别 MLU580，但尚不能把它验收为芯片本体。华为应纳入 Ascend 960 和 Ascend 970，其中 970 只做规划期研究。AMD 应纳入 MI430X 和 MI455X 内层 GPU package；MI440X、MI308X 和 MI500 Series 仍不满足本次物理身份与信息充分性双门槛。除上述对象外，没有在截止日前的一手来源中发现需要立即加入计数分母的新对象。

## 建议基数与后续未决项

建议计数基数按以下方式更新：

$$
41 + 7\text{ 个观察项提升} + 1\text{ 个 MI455X 封装裁决} = 49
$$

其中 7 个由观察状态提升的对象是 Rubin CPX、TPU 8t、TPU 8i、Trainium4、Ascend 960、Ascend 970 和 MI430X；第 8 个新增计数是 MI455X 内层 GPU package。正式修改范围表时，还要同步把 Rubin CPX 的物理层级从 `package` 改为厂商已明确的 `die`，把 MI430X 从 `unresolved` 改为 `package`。

Trainium4 与 Ascend 970 纳入后仍要等待绝对规格和芯片结构，现阶段不能把资料卡标成规格完备。Rubin Ultra、LP35、Feynman GPU、LP40、MLU580、MI440X 等待更完整的芯片级资料；MI308X、NVIDIA L2 和 H20 BFX 等待底层裸片或封装映射闭合。MI455X 的术语还需在正式数据合并前核对 brochure 中的内层 GPU package 与新版 CDNA 页面所称 GPU EAM，避免把内层封装和外层增强加速器模组（Enhanced Accelerator Module，EAM）写成同一个对象。
