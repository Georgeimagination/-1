# 最新芯片范围修订官方证据抽查（2026-08-17）

## 抽查口径与结论

本次只核对厂商一手资料，不使用媒体或第三方规格库。纳入门槛沿用本轮范围修订口径：对象已经被厂商正式命名，物理身份能够落到裸片（die）或单颗芯片封装（package），并且一手资料已经给出足以开展架构研究的计算、存储、数据格式、专用单元或互联信息。是否已经交付或一般可用只记为状态，不作为排除条件。厂商仅称 `chip`、尚未公开裸片与封装细节时，`package` 只能作为项目内部的保守容器，不能写成厂商已经确认的封装结构。

抽查支持修订稿的主体方向：Rubin CPX、TPU 8t、TPU 8i、Trainium4、Ascend 960、Ascend 970、MI430X 和 MI455X 内层 GPU package 均可进入计数。其中 Rubin CPX、两颗第八代 TPU、MI430X 和 MI455X 的证据较完整；Trainium4、Ascend 960 和 Ascend 970 只能按前瞻对象研究，公开数值必须保留 `projected` 或“设计目标”条件。Rubin Ultra、LP35 和 LP40 已有正式路线图身份，但独立芯片规格仍不足，保留观察项合适。Feynman 是正式世代名，官方只说该世代会有一颗新 GPU，没有公布 GPU 的正式 SKU 名；范围表中的 `NVIDIA Feynman GPU` 应视为工作标签，建议改成“Feynman 世代未命名 GPU”。

## 对修订稿的独立意见

`审计/训练推理芯片名单冻结.csv` 对 Rubin CPX 改为 `die` 是正确修正；TPU 8t/8i、Trainium4、Ascend 960/970 采用 `package` 时，应在对象说明中保留“专有单器件的保守容器，厂商未公开封装细节”这一限定。MI430X 的 `package` 有官方直接措辞支持。MI455X 内层 GPU package 可以计数，但范围表中“EAM 承载四个 GPU packages”的关系不成立：官方图示是四颗 MI455X GPU 组成一个 compute tray。正式合并时应把 package、EAM 和 compute tray 三层分开，并把每个 EAM 内 package 数量保持为未公开，不从示意图反推。

本次没有发现需要把八个计数候选降回观察或排除的反证，也没有发现四个 NVIDIA 观察项已经公开到足以转为计数的独立芯片规格。Feynman 观察项还需修正名称，当前只是世代级工作标签。结论只确认范围门，不代表这些对象的资料卡已经达到规格完备状态。
