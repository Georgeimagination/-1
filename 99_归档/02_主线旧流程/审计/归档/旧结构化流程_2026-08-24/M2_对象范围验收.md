# M2 对象范围验收

验收日期：2026 年 8 月 12 日  
状态：已通过  
范围：AWS、Google、NVIDIA、AMD、Groq、华为和寒武纪的高风险对象身份；本轮不采集规格事实。

## 验收依据

总控复核了三份身份核对交接及三份独立复核：

- `审计/子代理交接/m2_scope_aws_google.md` 与 `review_scope_cloud.md`；
- `审计/子代理交接/m2_scope_nvidia_amd_groq.md` 与 `review_scope_west.md`；
- `审计/子代理交接/m2_scope_huawei_cambricon.md` 与 `review_scope_china.md`。

裁决结果另存为 `审计/M2_对象范围映射.csv`。该表逐行记录 56 个高风险候选的处理方式、正式对象 ID、最终厂商、对象类型、建卡动作和保留条件。原始 `object_candidates.csv` 继续作为 M0 的 173 行候选快照，不用后来的裁决覆盖历史输入。

## 已接受的对象边界

AWS 的 EC2 instance type 统一使用 `cloud_instance`。Inf1 和现有 Trn2 family 是家族容器，暂时沿用同一枚举，但不得承载某个尺寸独有的事实。Google 的 `ct6e-standard-*` 也是 TPU VM machine type 家族，使用 `cloud_instance`；TPU v3 Pod、TPU 8t Superpod 和 TPU 8i Pod 则是 `pod` 系统对象。8t 与 8i 只建立 announced 观察对象，不制造尚未出现的云配置。Trainium4 的架构身份保留，所谓 NVLink Fusion 未来系统没有独立产品名或固定组成，仍停留在候选层。

NVIDIA Groq 3 LPU、LPX compute tray 和 LPX rack 归 `VEN-NVIDIA`，第一代 Groq 产品仍归 `VEN-GROQ`。LP30 的物理层级尚未确定，暂不导入。A800 数据中心候选、H800 和 H20 都覆盖多个物理 SKU，必须先按厂商固定名称拆分；A800 40GB Active 是工作站卡，不进入当前数据中心样本。L20 与 L2 已按独立卡导入并关联 Ada Lovelace。H20 BFX 的官方架构归类存在版本冲突，暂不建立对象或架构关系。

AMD MI308X、MI350P、CDNA 5、MI455X、Helios 和 CDNA 6 的对象身份已经固定。MI308X 暂不关联 CDNA 3；MI455X 与 CDNA 5 已建立关系，截止日状态仍按 announced 处理。Helios 是 OEM/ODM 参考机架，不是 AMD 可订购成品。MI440X、MI430X 缺少明确物理形态；MI500 Series 还是产品系列，当前 `object_type` 没有无损表示，三者继续留候选。

寒武纪的 `MLUarch05`、BANG v5.0 和 `__BANG_ARCH__=592` 分属物理架构名、待核软件架构目标和编译标识，不能合并。MLU570 封装与同名板卡分开；MLU370-M8、MLU570 和 MLU590 的新增映射仍受 CNToolkit 正文不可访问限制。M1 已有的 MLU590、H8 和 M9 对象保留，不能从名称反推包含数量或供货状态。

华为 CloudMatrix384 按硬件超节点建立 `pod`，其上的云服务另建候选。Atlas 800 A3 是独立风冷超节点，不是 800T/800I 的总称；三者分别保存。Atlas 850、850E 和 860 也是三个对象，不预设改名或继承。Atlas 950 只建一个 SuperPoD 对象，64、1024 和 8192 NPU 保存为带日期和状态的条件化配置。Ascend 950PR 与 950DT 是两个封装，共享一个 Ascend 950 裸片对象。

## 正式数据变更

本轮在 M1 的 14 个对象上新增 37 个范围裁决对象，并为第一波架构工作包预留 20 个稳定对象 ID。正式对象表现在有 71 个对象，其中 29 个是架构代际对象。新增 7 条已复核关系：L20/L2 到 Ada Lovelace、MI350P 到 CDNA 4、MI455X 到 CDNA 5、Helios 包含 MI455X，以及 950PR/950DT 各自包含共享 Ascend 950 裸片。正式关系总数为 20。

预留对象只固定身份、层级和外键，不表示资料卡或事实已经完成。第一波工作包必须继续写来源、字段要求、事实、冲突、完整度和最小来源筛选，不能把对象表中的 `reviewed` 当作规格已核验。

56 行范围映射的处理结果为：29 行新建对象、2 行新建观察对象、1 行重分类后新建、5 行复用既有对象、3 行合并到同一正式对象；其余 16 行分别进入拆分、延期、冲突保留或排除。明确延期也属于范围裁决，不用猜测类型或名称凑齐对象数。

## 验证结果

正式数据校验通过：

```text
PASS: 32-table research data model; 40237 checks executed.
Registry: 323 columns, 488 enum values.
```

`objects.csv` 有 71 个唯一 `object_id`，`object-relations.csv` 有 20 个唯一关系 ID；两表均保持 UTF-8 无 BOM。六份身份核对与独立复核文档的 report-humanizer 机器扫描均未发现可识别的 AI 痕迹；总控按 docs 场景回读了对象名、数字、日期、状态、厂商归属和关系方向，没有发现需要改写的模板腔。

第一次直接调用校验脚本时，本机 PowerShell 执行策略拒绝加载脚本；这是本地运行策略限制，不是工作区沙箱、用户审批、自动审批复核或脚本实现错误。改用显式 `-ExecutionPolicy Bypass` 启动同一只读校验器后成功运行。CNToolkit HTTP 401 仍属于远端服务访问限制，相关寒武纪对象因此保持待核。
