## 迁移目的

前置专题用于确定训练与推理芯片研究应关注的架构问题，49 款芯片主线负责原始资料筛选、规范事实维护、最小来源选择和一芯片一文档。两类工作分到独立顶层目录后，项目根目录只承担导航和范围约束。

本次只调整目录和恢复入口。原始资料、固定语料、正式数据、来源筛选记录、最小来源选择运行、资料卡和历史审计均不得因迁移发生语义变化。

## 恢复条件

迁移完成后须满足以下条件：

1. `02_主线调研-49款芯片资料库/` 作为 `RootPath` 时，32 张正式表和全部 `local_path` 均可解析；
2. `论文/`、`数据/`、`最小参考资料库/`、专题 `原文/` 和合并备份的文件数、字节数、内容聚合哈希与迁移前一致；
3. 来源家族、来源版本、访问入口、逐来源断言、筛选、覆盖、冲突、检索、选择运行和选择成员全部保留；
4. 前置专题脚本从脚本自身位置解析专题目录，不再依赖旧绝对路径；
5. 主线收集脚本从脚本自身位置解析新运行根，PowerShell 校验脚本的默认根仍指向主线目录；
6. 根目录和两个子目录的 README 能分别说明工作目的、恢复顺序和运行命令；
7. GA100 工作包保持暂停，不能把迁移前未验收的子代理输出当作正式输入。

## 验收结果

两个目录已经按映射完成物理迁移。项目根目录现只保留两个调研目录、`README.md` 和 `AGENTS.md`；主线内部的 `论文/`、`清单/`、`数据/`、`最小参考资料库/`、`资料卡/`、`审计/`、`进度/` 与 `scripts/` 相对层级没有变化。

迁移后重新计算的七组文件数、字节数和内容聚合 SHA-256 与迁移前逐项相同。32 张正式 CSV 仍为 2,160,328 字节，内容聚合 SHA-256 仍为 `e9297ea7edb4e4eb9d15a602767fca5b0a1da5a1a72ebdf188d94f389e51a6b5`。这次迁移没有改动正式表、原始论文、专题固定语料、最小参考资料库、合并备份或既有主线资料卡。

恢复路径检查读取了 153 个来源入口，其中 79 个有本地文件；79 个路径均为主线根下的安全相对路径，文件全部存在，79 个 SHA-256 全部匹配。32 张正式表可按 `schema-columns.csv` 找到，11 次选择运行和 106 个选择成员的引用完整。新增的跨平台检查脚本以默认根和显式 `--root` 两种方式运行，结果均为：

32 张正式 CSV 共解析 6,965 行，没有列数错误。根目录和两个子目录的关键入口共检查 27 个本地 Markdown 链接，没有断链；扩展检查覆盖 398 份活动 Markdown、137 个本地链接，只发现一处既有提交标题 `[Docs](mlu-ops)` 被正则表达式误判为本地链接，不是迁移断链。

## 脚本恢复

`Test-SourcePool.ps1` 原本就从脚本位置推导主线根。`Validate-ResearchData.ps1` 和 `Test-ChipScope.ps1` 已采用同样的默认根规则，因此从任意工作目录调用时都能定位 `02_主线调研-49款芯片资料库/`；仍可用 `-RootPath` 显式覆盖。

`collect_references.py` 不再写死原作者机器路径。它从脚本位置确定主线根和两个历史项目，默认把结果写入 `tmp/reference-collection-preview/`；只有审计预览后显式使用 `--apply` 才能写正式资料池。脚本帮助信息和路径推导已经实跑，两个历史项目与新主线根均可定位。

前置专题的三项审计脚本和 S05 联系表脚本也改为从脚本自身位置解析专题根。五个 Python 脚本均通过语法编译检查。系统 Python 有 `pypdf`，但没有 `lxml` 和 Pillow；Codex 工作区自带 Python 已确认同时包含 `pypdf 6.10.0`、`lxml 6.1.1` 和 `Pillow 12.3.0`，专题可以用该运行时恢复。

## 运行时限制

当前 macOS 环境没有 `powershell` 或 `pwsh`，因此本轮无法实跑三个 PowerShell 完整校验器。这是工具运行时缺失，不是用户拒绝、沙箱拒绝、审批失败、数据错误或迁移脚本错误。正式 CSV 内容与迁移前完全一致，本地路径和哈希也已通过跨平台检查，所以目录迁移可以接收；下一次在 Windows 恢复主线、且在任何正式数据写入之前，仍应补跑 `Test-SourcePool.ps1`、`Test-ChipScope.ps1` 和 `Validate-ResearchData.ps1`。

两条只读盘点命令曾因 zsh 对空通配符直接报错而失败，属于命令写法问题；随后改用 `find` 重跑并完成同一检查，没有产生写入。另有两次只读状态检查使用了任务台账中不存在的列名而触发 `KeyError`，属于操作者字段名误判；按真实表头改用 `verification` 后复查通过。三个并行辅助审计因长时间未形成交接，由主代理主动中断；它们没有修改正式文件，关键路径、脚本和恢复链由主代理重新核对。

## 裁决

目录迁移通过，数据清洗和逐芯片调研的恢复入口已经建立。GA100 工作包仍按用户要求暂停；若以后恢复，必须先在 Windows 补跑上述三个 PowerShell 校验器，再从 `进度/当前状态.md` 记录的停点重新开始复用审计。
