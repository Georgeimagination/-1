# 项目协作说明

## 项目目标与范围

本目录要建立两项可持续维护的成果：

1. NVIDIA、Google、AWS、Groq、寒武纪、华为和 AMD 的训练与推理芯片综合资料卡，每款芯片一份可独立阅读的文档；
2. 与资料卡逐条对应、经过内容去重的最小参考资料库。

主线只统计芯片本体：`die` 和表示单颗芯片封装的 `package` 可以进入主线，`architecture_generation` 只作证据支持。厂商已经正式命名、物理对象能够落到芯片本体，且一手资料足以开展架构研究的对象，即使尚未一般可用，也进入研究范围；设计期目标与已发布规格分开记录。模组、加速卡、云实例、底板、服务器、机架和 Pod 不计主线完成度；已有记录保留审计价值，但不继续补缺。49 个芯片对象已经冻结，当前按唯一名单逐芯片完成数据工程，最后生成一芯片一文档。主线现阶段不继续做跨芯片架构差异分析或跨厂商排名；用户明确要求的19份固定语料专题已在隔离目录完成，不改变主线范围。

相邻目录 `调研-训练推理芯片调研` 与 `调研-训练推理芯片调研-codex-v3` 是历史初步调研，只作为资料线索和旧记录读取。新的资料卡、数据、审计记录、下载文件和报告全部写入本目录；历史报告不能替代原始来源支撑关键规格。

## 证据与数据约定

每条关键规格拆成可独立核验的原子事实，至少包含产品对象、字段、原值、单位、条件、对象层级、来源标识和原文定位。资料卡中的关键字段必须能回到页码、表格、章节、网页标题或其他稳定定位。

来源强弱按它对具体事实的支持能力判断。固定版数据手册、架构白皮书、官方开发文档和原始论文优先；独立微基准、拆解和可复现实测用于补充或验证。官方一手资料已经覆盖产品身份和目标字段时停止媒体扩搜。媒体资料只有提供明确缺口所需的独有实测、直接采访、产品状态或矛盾证据时才定向保留；只复述更强来源的材料不进入最小参考资料集。

原始资料不因筛选而删除。被判为重复、过时、低相关或只作线索的来源保留筛选记录，并注明被哪些来源覆盖或为何不进入正式参考资料。

最小来源集必须保存可复现的反向移除记录。已复核的 selection run 要列出范围、算法版本、成员、入选角色和不可替代理由；事实集合变化后重新运行，不能沿用旧结论。直接事实的 `evidence_state` 按不同 `source_id` 数量计算，同一来源的镜像、不同 endpoint 或重复断言不增加来源数。

同一指标不得混用以下口径：

- 芯片、裸片、封装、模组、加速卡、服务器、机架和集群；
- 稠密和稀疏、理论峰值和持续实测；
- 输入精度、乘积精度、累加精度和输出精度；
- 单向、双向、线路聚合、有效载荷和系统总带宽；
- GB 与 GiB、十进制与二进制单位。

未知数值不得写成零。使用 `not_public`、`not_found`、`not_applicable`、`conflicting_unresolved` 或 `pending_verification` 等正式状态。只有一手资料明确说明未公开时才用 `not_public`；完成计划检索仍无可靠结果时用 `not_found`。根据公开数据计算的结果必须保留原始输入、公式、单位换算和适用范围。

## 多代理协作约定

主代理负责字段字典、全局标识、共享数据表、来源筛选规则、合并和最终验收。子代理按厂商或独立审查任务分工，只写各自的厂商目录或交接文件，不并发修改全局 CSV、索引、README、AGENTS 或研究计划。

49 款芯片由同一个主会话顺序总控。芯片是正式推进和验收单位，来源是阅读与抽取单位；一份涉及多款芯片的资料只做一次来源级精读，当前芯片之外的内容可以留作审计线索，但不得提前写入其他芯片的正式事实。每次只允许一个芯片工作包进入正式写入阶段。

子代理不使用 Luna，也不使用 `medium` 或 `ultra`。Terra 的最低推理强度为 `high`，默认 `xhigh`，最高 `max`；Sol 默认 `high`，复杂专题与高风险判断使用 `xhigh`，最高 `max`。确定性的文件、表格、哈希和精确 ID 映射可以使用 Terra high；通常的来源盘点、覆盖核查和低歧义抽取使用 Terra xhigh；核心资料主读和原子事实抽取使用 Sol high；对象层级、复杂架构专题、负载与芯片属性分层、来源冲突和最终独立复核使用 Sol xhigh，持续无法裁决的最高风险事项才升到 Sol max。需要显式指定模型和推理强度时，给子代理有限上下文、明确输入文件和可核验交付物，不继承整个长会话。

每个子代理交付时必须列出：任务状态和输入，处理的型号与对象层级，读取的来源，已完成事项与验证，全部写入文件，尚未核实的字段，来源矛盾，被筛除资料及理由，以及建议的下一步。未经主代理复核的资料卡标为草稿，不能进入完成清单；子代理自行报告完成也不能直接改变全局台账状态。

同一厂商的高风险资料卡应由不同于初稿作者的代理复核。主代理在合并前检查对象层级、精度、单位、来源定位和事实状态；跨厂商结论仍留到后续独立阶段。

M2 子代理只写自己的 `审计/子代理交接/m2_staging/<work_package>/`。卡片草稿和结构化片段在总控验收前不进入正式厂商目录或全局 CSV；对象 ID、共享来源 ID 和关系由总控预留并顺序合并。
