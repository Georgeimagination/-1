# 芯片分析模板试填验收

## 结论

0.1版模板通过两类对象的只读试填：H100代表公开规格较完整、训练与推理均可使用的通用加速器；Inferentia2代表厂商定位偏推理、部分微架构和系统数据未披露的对象。试填没有向正式数据表写入新事实。

| 验收问题 | H100 | Inferentia2 | 结论 |
| --- | --- | --- | --- |
| 能否固定单一对象层级 | SXM5模组 | 保守的package事实容器 | 通过 |
| 能否隔离裸片、卡、服务器与软件 | GH100、HGX/DGX均留在外部 | EC2 Inf2实例与Neuron Compiler留在外部 | 通过 |
| 能否区分输入、累加和格式路径 | BF16/FP8累加可记录，缺失项保留 | BF16/FP16→FP32可记录，cFP8/TF32语义留缺 | 通过 |
| 能否区分稠密/稀疏、峰值/实测 | H100两类峰值分开 | 只有厂商理论峰值，不虚构实测 | 通过 |
| 能否保留单位冲突 | 无当前冲突；3 TB/s与3.35 TB/s按版本分开 | 820 GiB/s与820 GB/s并列未决 | 通过 |
| 能否计算机器平衡点 | BF16稠密路径可算 | 两个带宽口径分别试算 | 通过，且不能合并冲突 |
| 能否计算状态适配比 | 缺具体工作负载状态，拒绝计算 | 缺具体工作负载状态，拒绝计算 | 通过 |
| 能否避免用途硬标签 | 不能由单个比值给H100贴标签 | 厂商推理定位与架构证据分开 | 通过 |

## 试填发现的模板要求

第一，`raw_value`和`normalized_value`必须同时存在，否则Inferentia2的GB/GiB冲突会被换算过程掩盖。第二，计算峰值必须带精度、稠密性和理论/实测口径，否则H100的多个Tensor路径会被误加或误比。第三，模板必须允许状态预算整段为空；缺模型、batch、上下文和并发时，拒绝计算比填一个通用常数更可靠。

两份试填分别见 `模板试填_H100.md` 和 `模板试填_Inferentia2.md`。最终正式数据未变更证明将在执行后哈希复核完成时补充到本专题审计目录。
